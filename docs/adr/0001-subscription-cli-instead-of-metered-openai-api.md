# 用订阅制 CLI 承担分析算力，而非已预算的 OpenAI API 层

> Status: accepted
> Date: 2026-08-05

## 决定

自动化分析（Recall Sweep 补捞、Claim 生成）通过本机订阅制 CLI 执行：**`codex exec` 为主，`claude -p` 为备**，两者共用同一套"喂 prompt、收 JSON"契约，由可切换的载体适配器封装。`openai_service` 与 `openai_research` 保持 `enabled=false`。

## 为什么这需要一份 ADR

代码库里存在一整套完备但从未通电的 OpenAI 分析层：结构化输出、重试、超时、熔断、预算预留、`API Usage` 计量账本、25 USD/月 hard cap 全部实现并测试完毕，PRD §6 也已批准该预算。未来读者看到这套设施闲置、而分析改由外部 CLI 子进程完成，必然会认为这是遗漏或倒退，并试图"修复"它。它不是遗漏。

## 取舍

运营方明确要求新增自动化不产生新的现金支出。两条路都能满足功能需求：

- **OpenAI API**：计量付费，成本可审计、可预算、可熔断，无并发与限流的人为约束，但每月产生真实账单。
- **订阅制 CLI**：边际现金支出为 0（订阅已付），但消耗订阅额度、受订阅限流约束，且成本不进入 `API Usage` 账本，因而无法用现有成本门禁度量。

选择后者的决定性因素是现金支出，而非技术优劣。

## 代价（必须知情）

1. **不是"零 token"，只是"零现金"。** CLI 调用照常消耗 token 与订阅额度，只是不走计量账单。任何声称该链路"免费"的表述都不准确。
2. **新增两个断供点**：本机休眠（已于 2026-07 造成过实际断供）、订阅限流或 CLI 登录态过期。两者都不会被 `API Usage` 预算门禁捕获，只能靠 RunLog 与失败告警发现。
3. **成本不可审计。** 现有成本治理体系对这条链路失效；`API Usage` 表不会记录它。

因此凡依赖该链路的产出，都必须能在链路不可用时降级而非阻断——参见 ADR-0002 与周报门禁降级。

## 回退路径

把载体适配器切到 OpenAI 服务并将 `openai_service.enabled` 置为 `true` 即可，无需改动生成器与校验器。这正是保留整套 OpenAI 设施而不删除的原因。
